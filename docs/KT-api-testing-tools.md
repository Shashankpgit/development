# KT — API Testing Tools: curl and Postman

---

## Why you need these alongside Swagger UI

Swagger UI is auto-generated by FastAPI. It's great for quick checks during development. But:

- You can't save and reuse requests easily
- You can't script it (run 10 requests in a loop)
- You can't share a collection with teammates
- You can't use it in CI/CD pipelines

**curl** and **Postman** solve these. Every backend engineer uses them daily.

---

## curl

curl is a command-line tool that makes HTTP requests. It comes pre-installed on Linux and Mac. No GUI, no install needed.

### Basic structure

```bash
curl [options] <URL>
```

### GET request

```bash
curl http://localhost:8000/health
```

Output:
```json
{"status":"ok","version":"0.1.0"}
```

### See the full response including status code and headers

```bash
curl -v http://localhost:8000/health
```

`-v` = verbose. Shows:
- `>` lines = what curl sent (request headers)
- `<` lines = what the server returned (response headers)
- The response body at the bottom

### See only the HTTP status code

```bash
curl -o /dev/null -s -w "%{http_code}\n" http://localhost:8000/health
```

Output: `200`

Useful in scripts — check if a service is healthy before proceeding.

### POST request with a JSON body

```bash
curl -X POST http://localhost:8000/notes \
  -H "Content-Type: application/json" \
  -d '{"title": "My first note", "body": "Hello Vault"}'
```

Breaking it down:
- `-X POST` — use the POST method (default is GET)
- `-H "Content-Type: application/json"` — tell the server you're sending JSON
- `-d '...'` — the request body (data)

### POST with an Authorization header (used in Phase 4)

```bash
curl -X GET http://localhost:8000/notes \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..."
```

### Pretty-print JSON output

curl output is raw. Pipe it to `jq` to format it:

```bash
curl -s http://localhost:8000/health | jq
```

Output:
```json
{
  "status": "ok",
  "version": "0.1.0"
}
```

If `jq` is not installed: `sudo apt install jq`

### curl cheat sheet for this project

```bash
# Health check
curl -s http://localhost:8000/health | jq

# Create a user (Phase 2)
curl -X POST http://localhost:8000/users \
  -H "Content-Type: application/json" \
  -d '{"username": "bob", "password": "secret123"}' | jq

# Login (Phase 4)
curl -X POST http://localhost:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "bob", "password": "secret123"}' | jq

# Call protected endpoint with token (Phase 4)
curl -s http://localhost:8000/notes \
  -H "Authorization: Bearer <paste-token-here>" | jq
```

## Postman

Postman is a GUI application for making and managing API requests. Think of it as a browser specifically built for APIs.

Download: https://www.postman.com/downloads/ (free)

### Core concepts

**Request** — one API call. Has a method, URL, headers, and optional body.

**Collection** — a folder of saved requests. You can organize by feature: `Auth`, `Notes`, `Passwords`. The whole team shares one collection.

**Environment** — a set of variables. Example:
```
base_url = http://localhost:8000    ← dev environment
base_url = https://vault.yourdomain.com  ← prod environment
```
Instead of changing URLs in every request, you switch environments.

**Variable** — a reusable value. After login, Postman can automatically save the token into a variable `{{token}}` — every authenticated request uses `{{token}}` instead of a hardcoded string.

### How to use the collection file in this project

We maintain a Postman collection at `vault/postman/vault.postman_collection.json`.

To import it:
1. Open Postman
2. Click **Import** (top left)
3. Select the file `vault/postman/vault.postman_collection.json`
4. All requests appear in your sidebar

### Postman vs curl — when to use which

| Situation | Use |
|---|---|
| Quick one-off test while coding | curl |
| Sharing requests with a teammate | Postman collection |
| Automated testing in a script | curl or Python requests |
| Exploring an unfamiliar API | Postman (easier to see everything) |
| CI/CD pipeline health checks | curl |
| Testing with complex auth flows | Postman (saves tokens automatically) |

In a real company you'll use both. curl for speed, Postman for organization.

## Real-world workflow

A typical backend engineer's day:

1. Write a new endpoint
2. Start the server
3. Hit it with curl once to verify it works at all
4. Open Postman, add a request to the collection
5. Test edge cases (missing fields, wrong types, unauthorized access)
6. Commit the updated Postman collection alongside the code

The collection becomes living documentation — it shows exactly how to call every endpoint with real examples.
