# Deployment Guide: Kong API Decoupling with Ownership Tags

## Overview
This guide explains how to deploy the Discussion Forum addon with complete API isolation from the core using Kong's `--managed-by` ownership tags.

## Prerequisites

### Environment Variables
```bash
export ENV_NAME=<your-environment>     # e.g., demo, staging, prod
export CLOUD_PROVIDER=azure            # or gcp
```

### Required Files from OpenTofu
The addon deployment script expects these files generated by OpenTofu:
```
opentofu/<CLOUD_PROVIDER>/<ENV_NAME>/
├── global-values.yaml         # Kubernetes context, namespace, etc.
└── global-cloud-values.yaml   # Cloud-specific settings (storage, networking, etc.)
```

If these don't exist, you must run:
```bash
cd opentofu/<CLOUD_PROVIDER>/<ENV_NAME>
terraform init && terraform apply
```

## Deployment Architecture

### Service Deployment Order
The addon must be deployed in this specific order:

```
1. discussion-forum-apis    ← Registers Kong routes with --managed-by=discussion-forum
2. discussion-forum-consumers ← Grants ACLs for new API groups
3. discussionmw            ← Discussion middleware service
4. nodebb                  ← NodeBB forum platform
5. groups                  ← Groups service
```

The `manage.sh` script handles this ordering automatically.

### Kong API Isolation via Tags

#### How It Works
Each service stamps a unique tag on Kong services it creates:

**Core Chart**:
```yaml
managed_by: core
# All ~470 core APIs get tagged: managed-by:core
```

**Addon Chart**:
```yaml
managed_by: discussion-forum
# All 31 addon APIs get tagged: managed-by:discussion-forum
```

#### Kong Sync Process

When `kong_apis.py` runs with `--managed-by=core`:

**Phase 1 — Decide what to CREATE/UPDATE**:
```python
all_services = get_apis(kong_admin_api_url)  # Fetch ALL services
# Compare with input YAML
# Create or update as needed
```

**Phase 2 — Decide what to DELETE**:
```python
owned_services = get_apis(kong_admin_api_url, managed_by='core')  # Fetch ONLY tag='managed-by:core'
# Delete anything not in input YAML
# Services with 'managed-by:discussion-forum' are INVISIBLE
```

#### Result: Perfect Isolation

```
Core Upgrade Scenario:
  ↓ Core chart runs kong_apis.py --managed-by=core
  ↓ Kong API: GET /services?tags=managed-by:core
  ↓ Returns: ~470 core services
  ↓ 31 addon services (tagged managed-by:discussion-forum) are INVISIBLE
  ↓ Safe to delete what's not in core YAML ✓

Addon Upgrade Scenario:
  ↓ Addon chart runs kong_apis.py --managed-by=discussion-forum
  ↓ Kong API: GET /services?tags=managed-by:discussion-forum
  ↓ Returns: 31 addon services
  ↓ 470 core services (tagged managed-by:core) are INVISIBLE
  ↓ Safe to delete what's not in addon YAML ✓
```

## Installation Steps

### 1. Prepare Environment
```bash
# Set required variables
export ENV_NAME=demo
export CLOUD_PROVIDER=azure

# Verify files exist
ls -la opentofu/azure/demo/global-*.yaml
# Should show:
# - global-values.yaml
# - global-cloud-values.yaml
```

### 2. Deploy Discussion Forum Addon
```bash
cd addons/discussion-forum

# Run the installation script
./scripts/manage.sh install azure

# The script will:
# ✓ Resolve helm dependencies (common chart)
# ✓ Deploy discussion-forum-apis (Kong routes with --managed-by=discussion-forum)
# ✓ Deploy discussion-forum-consumers (Kong ACLs)
# ✓ Deploy discussionmw service
# ✓ Deploy nodebb service
# ✓ Deploy groups service
# ✓ Patch LMS with groups-service URL
```

### 3. Verify Deployment
```bash
# Check pod status
kubectl get pods -n addon
# Should show: discussion-forum-apis job completed, services running

# Verify Kong API registration
kubectl exec -n addon pod/kong-admin -- \
  curl 'http://localhost:8001/services?tags=managed-by:discussion-forum' | \
  jq '.data | length'
# Should return: 31

# Verify core APIs untouched
kubectl exec -n addon pod/kong-admin -- \
  curl 'http://localhost:8001/services?tags=managed-by:core' | \
  jq '.data | length'
# Should return: ~470
```

## Uninstallation Steps

### 1. Remove Discussion Forum Addon
```bash
cd addons/discussion-forum

# Run the uninstallation script
./scripts/manage.sh uninstall

# The script will:
# ✓ Uninstall all addon services
# ✓ Remove Kong routes (tagged managed-by:discussion-forum)
# ✓ Patch LMS to clear groups-service URL
```

### 2. Verify Cleanup
```bash
# Check services removed
kubectl get services -n addon | grep discussion
# Should return: (empty)

# Verify Kong APIs removed
kubectl exec -n addon pod/kong-admin -- \
  curl 'http://localhost:8001/services?tags=managed-by:discussion-forum' | \
  jq '.data | length'
# Should return: 0

# Verify core APIs still present
kubectl exec -n addon pod/kong-admin -- \
  curl 'http://localhost:8001/services?tags=managed-by:core' | \
  jq '.data | length'
# Should return: ~470 (unchanged)
```

## Troubleshooting

### Error: "directory ../../../common not found"
**Cause**: Chart.yaml has incorrect path to common dependency

**Solution**:
```yaml
# Wrong
repository: file://../../../common

# Correct
repository: file://../../../../helmcharts/library/common
```

### Error: "ENV_NAME environment variable is not set"
**Cause**: Environment variable not exported

**Solution**:
```bash
export ENV_NAME=demo
./scripts/manage.sh install azure
```

### Error: "OpenTofu global values not found"
**Cause**: Missing OpenTofu output files

**Solution**:
```bash
cd opentofu/azure/demo
terraform init && terraform apply
# This creates global-values.yaml and global-cloud-values.yaml
```

### Error: "Kong admin not reachable"
**Cause**: Kong service not ready

**Solution**:
```bash
# Wait for Kong to start
kubectl wait --for=condition=ready pod -l app=kong -n addon --timeout=300s

# Check Kong logs
kubectl logs -n addon -l app=kong --tail=50
```

### Kong APIs Not Tagged
**Cause**: Job didn't run or completed with error

**Solution**:
```bash
# Check job status
kubectl get jobs -n addon
kubectl logs -n addon <job-name>

# If job failed, check:
# 1. Kong admin URL is correct in values.yaml
# 2. Kong is running and accessible
# 3. API ConfigMap was created successfully
kubectl get configmap -n addon
```

## Configuration

### Addon Values (`helmcharts/discussion-forum-apis/values.yaml`)

**Kong Configuration**:
```yaml
kong_admin_url: kong-admin      # Kong admin service name
kong_admin_port: 8001           # Kong admin port
managed_by: discussion-forum    # Ownership tag
```

**Service Endpoints**:
```yaml
group_service_url: "http://groups-service:9000"
discussion_service_url: "http://discussionmw:3001"
```

**Rate Limiting**:
```yaml
high_rate_limit_per_hour: "1000"
medium_rate_limit_per_hour: "500"
low_rate_limit_per_hour: "100"
```

### Core Values (`helmcharts/edbb/charts/kong-apis/values.yaml`)

**Kong Configuration**:
```yaml
managed_by: core    # Ownership tag for core APIs
```

This ensures core APIs are tagged and scoped correctly.

## Safety Guarantees

### Migration Safety
On first deployment after this change:
1. Core chart runs with `--managed-by=core`
2. Existing untagged services are UPDATED (not deleted) to add tags
3. No API deletion occurs during migration ✓

### Concurrent Deployments
Core and addon can deploy concurrently:
- Core fetches only `managed-by:core` services
- Addon fetches only `managed-by:discussion-forum` services
- No conflicts or deletions ✓

### Safe Upgrades
Core chart can be upgraded without affecting addon:
1. Core job runs, fetches `managed-by:core` services
2. Addon services invisible to core sync
3. Core deletion only affects core APIs ✓
